## Contract

- The beta update preference is located in Settings → App info and is used by manual update checks.
- App info starts with Version. Television playback capabilities sits between update controls and project/license links, with 24dp spacing above and below; remote focus follows the visible order. Project and license links have no redundant trailing descriptions.
- Cancelling the update prompt returns focus to the invoking check row. Returning from Android's installer (including cancellation) restores the last focused App info row after the app window regains focus; restoration is consumed once and must not steal focus on later navigation.
- Manual checks keep the check row focusable while pending and ignore repeat activation. Error details appear only on failure below the check row; normal states do not reserve an empty error panel.
- Pressing Up on Version scrolls App info back to its start, revealing the complete logo/header while keeping focus on Version.
- Entering App info from the sidebar preserves the top position when Version is already fully visible. Focus scrolling in App info moves only enough to reveal an offscreen row, rather than repositioning visible rows at the TV focus pivot.
- Settings exposes one manual update check. Available updates reuse the startup `RobustUpdateDialog`, including its existing confirmation, download, and installer callbacks; Settings has no separate install row or release-notes panel.
- Version metadata is checked automatically when the app first becomes interactive and whenever the running app wakes from screen-off/background. This covers Android TV devices that keep the process alive while the display sleeps. Automatic checks only fetch metadata; downloading and installing still require the user's confirmation in the existing update dialog.
- App Info retains one manual update check. The screen distinguishes checking, current, available, downloading, and failure states; an available update shows its version and release notes before the user accepts it.
- OTA selects `apkUrls` by Android `Build.SUPPORTED_ABIS` preference order, using the first nonblank matching URL. This uses OS-supported ABIs rather than CPU hardware or current process bitness, so 32-bit Android on a 64-bit CPU receives `armeabi-v7a`. Stable and beta manifests use the same selection. If no URL matches, use the universal `apkUrl`; never guess an asset filename.
- Release manifests list only uploaded ABI assets. Keep `apkUrl` for released clients that only read that field. Compatibility owner: Honorebi release maintainers; dependency: pre-ABI-selection clients. Remove the legacy field only after those clients are no longer supported; review at the next major release. Regression coverage includes legacy-only manifests and missing/blank ABI URLs.
- Accepting an available update downloads the APK and opens Android's installer. A failed check or download remains visible with the check action available for recovery.
- Updates stream the selected APK into a full-install PackageInstaller session, with the app package name, label and icon, and commit through an explicit mutable PendingIntent to a non-exported result receiver. Android's installation confirmation remains required. No ACTION_VIEW/FileProvider staging fallback remains. Session confirmation replaces the legacy completion-page path; the old Done/Open page is not part of the Session contract.
- Only one download/install may be pending. A committed session is owned by Android; cancellation or failure before commit abandons it. Result callbacks must match the persisted session ID; stale callbacks cannot alter the current operation. Missing confirmation intents and installer failures expose a reason, stable status code and retry instruction. User cancellation returns to the existing screen without reporting success. Result state survives updater process recreation; installation success must come from Android, never from commit alone.
- The initiating app owns the update mechanism: a version containing this change is still installed by the previous version's mechanism. Its later outgoing updates use Session. The installation flow, displayed metadata, cancellation, retry and self-update process replacement require real TV acceptance before claiming this defect fixed.
- The result receiver name/action are an outgoing update contract: subsequent APKs must retain the receiver while a preceding released updater can target them. Foreground confirmation is retained across process recreation and launched only by a resumed MainActivity. If Android terminates the app for replacement, reopening reads the persisted result; a package-manager-confirmed version increase also establishes success. A missing session without that evidence is a recoverable interrupted-install error.
- A fresh install defaults live and recorded playback subtitles to ON. Existing explicit user preferences remain unchanged, and the playback controls continue to use those preferences.
- Subtitle preferences remain independently switchable in Playback settings.
